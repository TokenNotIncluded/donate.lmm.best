# Stablecoin checkout extension

Mode: Operate. Scope: the public donation form and its on-chain receipt, plus the
chain configuration inside Admin → Payment methods. Visitors choose a transfer
and verify its receipt; the administrator configures and checks receiving routes.
This is a local extension of the pinned world in DESIGN.md. It has no new visual
world, approved comp, tournament or seed.

## Built path

- Asset and network are native selects above the donation action. Selecting a
  stablecoin uses USD amounts; the network list follows the selected asset.
- The receipt names the network/token, then shows exact expected and confirmed
  amounts, a separate unconfirmed amount when different, the transaction result,
  its reason, and the minimum receipt with the quoted tolerance.
- The white wallet action pre-fills the remaining transfer amount. Address, copy,
  payment/address QR selection and fee guidance sit in an optional disclosure.
  Transaction-ID submission stays directly available, with explorer links for
  submitted transaction results.
- Receipt snapshots arrive through SSE; manual recheck stays available. Connection
  interruptions have a status message. Expiry and confirmation-deadline reasons
  give explicit recovery instructions; a sent transfer is never presented as
  locally cancelled.
- Malformed transaction IDs show recovery text next to the field, connected by
  `aria-describedby`; invalid submissions focus and scroll to that field, and
  editing clears its invalid state.
- The GitHub source link sits below the existing footer. Its star count appears
  only when a genuine fetched count is available; fetch/cache time is in its title.

## Admin extension

Shared receiving addresses cover EVM, TRON and Solana, with per-network overrides.
The default underpayment tolerance is 1%, adjustable in 0.01% steps. Network and
token checkboxes are visible; each advanced JSON editor starts collapsed, with a
node/token check beside it. The separate chain form starts 30px below the existing
payment-method controls. Existing optional donor data, Passkey and legal paths
remain part of the incumbent flow.

The optional chain-event disclosure configures incoming events that only wake
server verification. Outgoing notification support remains available in
Notifications; the user deferred it and no recipient was activated in this task.

## Layout and documentation boundary

The public column retains its existing 430px maximum and narrow-screen gutters.
Choice rows use a 90px label track; thin square borders, white focus rings and
native controls follow the existing material. Receipt numbers use monospace and
wrap when needed. Admin fields become one column at 620px.

The pinned root DESIGN.md is retained with a link here; no global format/token
migration or new north star is inferred. The [sidecar](../design.json) contains
only extracted extension snippets, motion and responsive metadata. Its specimens contain no
receiving addresses or paid receipt values.

## Evidence and finish

The local fixture screenshots cover [desktop choices](../review/choice-desktop.jpg),
[mobile choices](../review/choice-mobile.jpg), [desktop receipt](../review/desktop.jpg),
[mobile receipt](../review/mobile.jpg), [desktop admin](../review/admin-desktop.jpg)
and [mobile admin](../review/admin-mobile.jpg). They are UI evidence,
not production/payment evidence: addresses and amounts are synthetic. Admin was
set to 1.25%; the older immutable quote retains 1% and naturally aged to expired.

The finish reviewer initially requested fixes for field-local transaction-ID
recovery and the 30px admin form separation. Both material fixes were resolved;
the same reviewer found the remaining scope clear and gave `ship` at that fix-list
scope. The detector ran once with a degraded parser fallback because optional
dependencies were missing; it was not rerun or reported as a full clean scan.

No new bitmap artwork ships in this extension. QR images are genuine,
payment-specific codes generated by the server at runtime; review JPGs are
non-shipping evidence, and incumbent artwork is unchanged.
